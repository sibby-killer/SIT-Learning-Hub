PART 2 PRODUCT VISION AND PURPOSE
======================================================================

## 5. PRODUCT OVERVIEW

SIT Learning Hub is a university learning and career-development platform designed to help students succeed academically while developing practical skills for the professional world.

The platform must go beyond traditional learning management systems.

Traditional university learning often concentrates on
- Lecture notes.
- Videos.
- Assignments.
- Examinations.
- Final grades.

SIT Learning Hub must also help students
- Understand why concepts exist.
- Understand how systems work.
- Apply knowledge to unfamiliar problems.
- Use relevant professional tools.
- Complete realistic practical activities.
- Develop independent problem-solving abilities.
- Build projects.
- Document their work.
- Develop a professional portfolio.
- Understand possible career paths.
- Identify their skill gaps.
- Continue learning after university.

## 6. PRODUCT PHILOSOPHY

Learn to understand.

Practise to master.

Build to gain experience.

Pass to progress.

Apply your skills to your future career.

The platform must not be designed exclusively around passing examinations.

A student who passes an examination but cannot apply the knowledge should be able to see the practical skills they still need to develop.

A student who completes a practical project but has not mastered the academic learning outcomes should also see what remains incomplete.

Academic mastery, practical competence and career readiness are separate but connected dimensions.

## 7. PRIMARY OBJECTIVES

The platform should

1. Provide structured university learning.
2. Make difficult concepts easier to understand.
3. Support examination preparation.
4. Provide a reliable past-paper bank.
5. Evaluate written answers.
6. Create personalised study calendars.
7. Track learning progress.
8. Teach practical applications.
9. Encourage project-based learning.
10. Develop professional skills.
11. Maintain a portfolio of completed work.
12. Provide a persistent personal AI teacher.
13. Provide career-development guidance.
14. Support multiple students.
15. Provide administrators with content-management tools.

## 21. ANSWER EVALUATION

When a student submits a typed answer, the system should evaluate it using

- Correctness.
- Conceptual understanding.
- Completeness.
- Reasoning.
- Method.
- Relevant terminology.
- Accuracy of calculations where applicable.

Feedback should contain

1. Score.
2. What was correct.
3. What was missing.
4. What was incorrect.
5. Why the mistake occurred.
6. Suggested correction.
7. Exact concept to revisit.
8. Recommended next action.

Do not simply return Correct or Wrong.

For numerical questions, use deterministic validation where possible.

For subjective answers, use a rubric and AI evaluation.

AI grading should be treated as an assessment aid, not unquestionable truth. Provide reviewer controls for important assessment content.

## 22. TOPIC PASS REQUIREMENT

Minimum topic pass mark 60%.

If the learner scores below 60%
- Show feedback.
- Recommend revision.
- Allow another attempt.
- Record the attempt.
- Keep the topic locked from progression.

If the learner achieves at least 60%
- Record the successful attempt.
- Mark the topic as passed.
- Unlock the next eligible topic.

The backend must control progression.

An AI response must never be trusted as the sole authority for unlocking topics.

## 23. UNIT ASSESSMENT

After the required topics are completed, provide a unit assessment.

The assessment should cover the unit learning outcomes.

Include
- Written questions.

- Application questions.
- Relevant past-paper questions.
- Supplementary questions.

Track
- Score.
- Attempt number.
- Time taken where meaningful.
- Questions answered.
- Learning outcomes assessed.
- Weak areas.

## 31. CURRICULUM MAPPING

External questions must be mapped using actual learning outcomes.

Do not map questions merely because their unit titles look similar.

Classify mapping confidence

HIGH
Strong alignment with verified learning outcomes.

MEDIUM
Reasonable alignment requiring reviewer confirmation.

LOW
Weak or uncertain alignment.

Only approved HIGH and reviewed MEDIUM questions should enter the main examination bank.

Keep LOW-confidence questions separate.

## 32. DUPLICATE DETECTION

Detect

1. Exact duplicates.
2. Near-verbatim repeats.
3. Repeated concepts.
4. Related but distinct questions.
5. Questions that only appear similar.

Use multiple techniques
- Text normalisation.
- Hashing.
- String similarity.
- Embeddings.
- Semantic comparison.
- Human review.

Do not rely entirely on an LLM.

Keep every original question occurrence.

Repeated questions should be linked into clusters.

Display
- Number of occurrences.
- Institutions.
- Academic years.
- Source documents.
- Page references.
- Similarity confidence.
- Explanation of why they were grouped.

Do not automatically delete questions because they are similar.

Do not claim a repeated concept guarantees that it will appear in a future examination.

## 34. EXAMINATION MODES

MOCK MODE

FINAL EXAM MODE

- Preserve the current page.
- Show the current unit and topic.
- Provide a conversation interface.
- Allow the student to ask questions.
- Allow the student to continue previous conversations where appropriate.

The assistant should not block important learning controls.

## 44. AGENT CONTEXT

- Student profile.
- Current semester.
- Current unit.
- Current topic.
- Topic learning outcomes.
- Approved notes.
- Available videos and resources.
- Previous assessment attempts.
- Previous mistakes.
- Learning progress.
- Study calendar.
- Practical projects.
- Skills practised.
- Career interests.
- Relevant portfolio evidence.

Only retrieve information relevant to the current request.

Do not expose one student's private data to another student.

## 45. AGENT CAPABILITIES

The agent should be able to

TEACH
Explain difficult concepts in different ways.

SIMPLIFY
Break complex ideas into smaller steps.

QUESTION
Ask the student questions to check understanding.

ASSESS
Evaluate typed answers using approved rubrics.

REVISE
Recommend specific topics to revisit.

PLAN
Help create realistic study plans.

TROUBLESHOOT
Guide practical work and diagnose errors.

PROJECT GUIDE
Help students plan and complete projects.

REVIEW
Review documentation and portfolio evidence.

CAREER MENTOR
Explain how skills relate to career paths.

REFLECT
Help students understand their strengths and gaps.

REMEMBER
Maintain useful learning context across sessions.

## 46. AGENT BEHAVIOUR

The agent should
- Encourage independent reasoning.
- Use simple explanations when the student is confused.
- Increase complexity gradually.
- Use relevant examples.
- Avoid pretending to know unverified information.
- Distinguish official curriculum content from general explanation.
- Admit uncertainty.
- Avoid doing every assignment automatically.
- Encourage the student to explain concepts in their own words.
- Avoid claiming mastery without evidence.

## 47. AGENT TECHNOLOGY

Preferred initial architecture

LangGraph
Agent orchestration and controlled workflows.

Groq
Initial model inference provider.

Database
Persistent learner context and conversation state.

Retrieval
Approved curriculum notes, learning resources and unit content.

Application tools
Controlled access to permitted application functionality.

Keep the model provider configurable so other providers can be added later.

Do not fine-tune a model for the first release.

Persistent memory should be based on structured application data and controlled retrieval, not merely a long prompt.

## 48. AGENT SAFETY AND PERMISSIONS

The agent must not
- Change academic results directly.
- Unlock topics independently.
- Modify student roles.
- Access other students' private records.
- Bypass examination restrictions.
- Execute arbitrary database operations.

## 95. NEVER COMPROMISE THESE PRINCIPLES

1. Do not turn the product into an examination-only application.

2. Do not treat watching a video as proof of mastery.

3. Do not treat reading notes as proof of mastery.

6. Do not treat completing a practical project as proof of complete academic mastery.

7. Do not fabricate university course content.

8. Do not fabricate examination papers.

11. Do not allow the AI to bypass backend rules.

12. Do not expose private student information.

13. Do not build features that have no real working functionality.

14. Do not mark unfinished functionality as complete.

15. Do not sacrifice maintainability for speed.
